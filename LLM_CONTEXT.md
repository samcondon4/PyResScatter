# PyResScatter: LLM Context & Architecture

## Overview
`PyResScatter` is a data-processing and analysis pipeline for microwave resonator scattering data (I and Q quadratures over swept frequencies). It is built tightly around `pandas.HDFStore` to efficiently store, organize, and track multi-dimensional parameter sweeps alongside raw, calibrated, and fitted data.

## 1. Data Structure & Hierarchy
The framework expects HDF5 files generated by `PyLabTools`.
* **MultiIndex Structure**: All data is indexed by `RecordGroup` (a string denoting a whole sweep sequence) and `RecordGroupInd` (a string denoting an individual step/trace within that sweep). Traces also use `RecordRow` for frequency points. Indices are 0-padded strings (e.g., `'%06i'`).
* **Hierarchical Folders**: The HDF5 file uses a hierarchical POSIX-style folder structure. 
  * The original raw data lives in `/base`.
  * A group like `/base` contains subgroups: `/base/data` (IQ traces), `/base/meta`, and `/base/proc_params`.
  * Processed or calibrated data is written to new, parallel hierarchical groups (e.g., `/process_0/data`, `/process_0/meta`).

## 2. Core Code Conventions
When writing or modifying methods in `ResonatorScatteringStore`, adhere to these rules:
1. **`in_group` / `out_group` Paradigm**: Data-transforming methods (like calibrations) take `in_group` (where to read) and `out_group` (where to write). 
2. **Safe Overwrites**: Methods must support `in_group == out_group`. To do this safely, write intermediate results to a temporary group (e.g., `/temp_cal_process`), and only replace the `out_group` at the very end of the function upon success.
3. **Bulk Metadata Copying**: When transforming data from `in_group` to `out_group`, always bulk-copy the corresponding metadata (`/meta`, `/proc_params`, etc.) to the new group outside of the main trace-processing loop for speed.
4. **Parameter-Only Outputs**: Methods that extract physical parameters but do not alter the IQ traces (e.g., `fit_res_params`, `find_min_mag_fr`) should *not* take an `out_group`. They should append their results directly into the `in_group` (e.g., `/base/res_params`).
5. **No `list.append` in Heavy Loops**: When generating large dataframes (like in `fit_res_params`), pre-allocate NumPy arrays and populate them via indexing, creating the DataFrame at the very end using `pd.MultiIndex.from_arrays`.
6. **Error Propagation**: When averaging fitted parameters, combine statistical scatter (Standard Error of the Mean) and the propagated fit error in quadrature ($\sqrt{\sigma_{SEM}^2 + \sigma_{prop}^2}$). Note that standard errors for complex variables (like $Q_c$) are represented as real magnitudes.
7. **Repacking**: Modifying HDF5 files leaves "dead space." The class includes a `_repack` staticmethod which is executed during `__init__` to migrate legacy flat files to the hierarchical structure without bloating the file size.
